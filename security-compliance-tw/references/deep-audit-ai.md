**何時讀**：語言模型參與了與信任有關的決策——聊天機器人與助理、RAG、持久化的代理記憶、
代理／工具呼叫迴圈、MCP 伺服器與用戶端、用不可信輸入組提示的程式碼、拿模型輸出去執行動作的程式碼。
要追的資料流是：**不可信內容 → 模型或記憶 → 能力、權限或 sink**。

與 `checks/sast-llm.md` 的分工：那一檔處理**掃描器會標的寫法**（提示拼接、模型輸出進 sink、
無白名單的工具迴圈、系統提示放金鑰）；本檔處理**掃描器看不到的委派層邏輯缺陷**。
傳輸、存取控制、查詢組裝、檔案系統與輸出渲染仍是一般的信任邊界，照 `deep-audit-hunting.md` 與各 check 審。

## 核心紀律（每個此領域的獵洞提示都要附）

- **單純的提示注入不是發現。** 要有程式碼層級的邊界失效：內容進入**另一個主體**的脈絡、
  動用了請求者沒有的權限、揭露了請求者讀不到的資料、或驅動了請求者自己碰不到的 sink
- 模型輸出、記憶、工具描述、MCP 回應都是**不可信輸入**。要指出的是授予權限、信任輸出、寫入持久狀態或餵給 sink 的那段程式碼
- **護欄提示（guardrail prompt）不是安全邊界。** 只算確定性的檢查、以資源為範圍的授權、隔離、綁定與受限的憑證
- 講清楚：攻擊者、受影響主體、實際執行身分、資源、確切動作、動用的權限、可觀察的影響。
  使用者**刻意**要求動用自己既有權限的請求，不會因為是模型執行的就變成委派缺陷
- **授權與動作綁定是兩個不同的控制。** 攻擊者控制的內容讓受害者在自己合法權限下執行了**他沒有刻意要求或核准**的動作——即使一般授權允許，也是動作綁定失效
- 有原始碼證據**且**有界本機驗證確立邊界與結果，才判 `confirmed`；需要供應商、部署、模型、渲染器或身分行為而本機觀察不到時，判 `needs_validation`

## 攻擊類別與對照

LLM26 = OWASP GenAI LLM Top 10 2026；ASI26 = OWASP Top 10 for Agentic Applications 2026。
編號只作對照參考，正式報告的編號一律以 `mapping.md` 為準。

### 脈絡、檢索與記憶

| 類別 | 要查什麼 | LLM26 | ASI26 | 相關 check |
|---|---|---|---|---|
| **經由檢索或匯入內容的間接注入** | 誰能寫入每個來源（RAG 文件、索引頁、檔案、信件、議題內文、工具回應、metadata）、檢索如何限定範圍、由誰的 session 消費、在那裡開啟了什麼能力。隔離、資源授權、與消費者意圖的綁定分開查 | LLM01 | ASI01、ASI06 | SAST-LLM-001 |
| **跨 session 或跨租戶的脈絡外洩** | 對話歷史、embedding、檢索結果、提示快取的鍵太寬。租戶與 ACL 過濾要在**查詢本身**與**每個快取鍵**裡；物件上存了租戶欄位，但替代查詢、共用快取或批次路徑漏掉它，就不算有強制 | LLM02、LLM09 | ASI06 | — |
| **持久記憶投毒** | 攻擊者內容或模型摘要寫進記憶，之後影響另一個任務、使用者或特權 session。查誰能建立／更新／合併／刪除記憶、來源與租戶範圍、低信任觀察是否變成持久的指令或事實。使用者自己存、只用於自己請求的記憶不算跨邊界 | LLM05 | ASI06 | — |
| **提示角色與來源混淆** | 不可信文字能冒充系統訊息、先前回合、工具結果、政策或記憶。找字串拼接、無型別的歷史、呼叫端可控的 role 欄位、序列化來回後遺失來源標籤。要確認偽造的來源真的改變了確定性的信任判斷 | LLM01 | ASI01 | SAST-LLM-001 |

### 工具與動作

| 類別 | 要查什麼 | LLM26 | ASI26 | 相關 check |
|---|---|---|---|---|
| **工具參數注入到下游 sink** | 模型產生的參數未經 handler 端驗證就進 SQL、shell、檔案、URL 抓取或特權 API。把工具 schema 當成輸入解析，逐欄追到 sink。結構化輸出只限縮形狀，**不**代表已授權、路徑或 URL 安全 | LLM10 | ASI02、ASI05 | SAST-LLM-002、SAST-INJ-001、SAST-INJ-002、SAST-INJ-003、SAST-SSRF-001 |
| **過度代理權與代理人混淆（confused deputy）** | 代理用服務身分或寬憑證執行，工具 handler 沒有對指定資源重新檢查**請求者**的權限。同時確認實際執行身分，以及呼叫者能否透過一般產品介面做同一件事。共用憑證但有逐使用者查詢範圍的不算缺陷 | LLM03 | ASI03 | SAST-LLM-003、SAST-AUTHZ-004 |
| **動作確認與核准綁定** | 使用者核准 A，執行時卻能換參數、換資源、換主體或延到後面的回合。核准要綁定：正規化後的工具名、完整參數物件、請求者、目標、金額、期限、批次成員。重試與恢復 session 時，核准不得授權被改過或重複的副作用 | LLM03 | ASI02、ASI09 | SAST-LLM-003 |
| **工具 schema 與 dispatcher 解讀不一致** | schema 接受別名、多餘欄位、重複鍵、型別轉換、巢狀自由物件或超範圍值，而 dispatcher 或 handler 的解讀不同。比對 schema 驗證、正規化、產生的綁定與 handler 預設值；值變成資源選擇器或資安選項的地方要再驗一次 | LLM10 | ASI02 | — |
| **無上限的委派動作迴圈** | 一個有界的請求可排入重複的花費、寄送、變更或外部 API 工作，卻沒有逐請求預算、逐動作授權、取消或冪等控制。用程式碼層級的計算與本機有界迴圈證明，**不要**把服務灌爆 | LLM06 | ASI08 | SAST-API-004 |

### MCP 與子代理信任

| 類別 | 要查什麼 | LLM26 | ASI26 | 相關 check |
|---|---|---|---|---|
| **子代理與 MCP 的信任繼承** | 委派的任務拿到完整 session、憑證、記憶或能力，而非最小權限。查每次呼叫帶入的主體與租戶、能力是否收窄、憑證的 audience、委派結果回來時是否當不可信 | LLM03 | ASI03、ASI07 | SAST-AUTHZ-004 |
| **MCP 伺服器與工具身分混淆** | 呼叫或結果依攻擊者可影響的伺服器名、工具名、請求 ID、資源 URI 或模型選的別名路由，而不是已驗證的連線與尚未完成的請求。查兩個伺服器能否宣稱同一工具、重連是否改變綁定、某伺服器的回應能否滿足另一伺服器的待決呼叫 | LLM04 | ASI04、ASI07 | — |
| **把 MCP metadata 與 schema 當政策** | 對端提供的工具描述、資源 metadata、提示、補全提示或 schema 被當成政策或授權。這些可以引導模型，但不能授予能力；找出 metadata 衝突時仍具權威的確定性白名單、伺服器身分檢查與 handler 授權 | LLM04 | ASI04 | — |

### 輸出與揭露

| 類別 | 要查什麼 | LLM26 | ASI26 | 相關 check |
|---|---|---|---|---|
| **不安全的輸出渲染** | 模型輸出進入會執行的 HTML、Markdown、模板、URL 或命令 sink，卻沒有該 sink 需要的編碼與政策。瀏覽器渲染要確認自動載入的資源與 CSP 或消毒；渲染器行為在 repo 之外時判 `needs_validation` | LLM10 | ASI05 | SAST-LLM-002、SAST-INJ-004、DAST-HDR-001 |
| **敏感脈絡萃取** | 組好的脈絡含憑證、他人資料、私有原始碼或本身就能授權的政策值，且使用者影響的輸出會把它們吐出來。揭露一般指令或行為描述、沒有跨資料邊界的，不算發現 | LLM02、LLM08 | — | SAST-LLM-004、SAST-AUTH-001 |

## 通用做法

- **先畫四張圖**：每個執行身分、每個能力、每個可寫入的脈絡或記憶來源、每個輸出目的地。再把起點的主體連到終點的權限
- **從有副作用的工具往回追**：dispatcher → schema → 確認 → 模型脈絡 → 檢索 → 匯入。從持久記憶的讀取點出發，追每個寫入者
- **比對同一動作的所有路徑**：直接、排隊、重試、恢復、批次、委派。最強的閘門必須在參數定案**之後**、每個副作用**之前**

## 驗證規則（回報此領域任何發現前）

1. 指出被跨越的邊界與可觀察結果：攻擊者、受影響主體或共用資源、執行身分、目標、未授權或未請求的動作或揭露
2. 代理人混淆：證明工具缺少「請求者 × 資源」的授權，且攻擊者無法透過正常介面做同一件事。
   動作綁定：改為證明攻擊者控制的內容讓受影響主體在自己的權限下執行了他沒有刻意要求或核准的動作
3. 記憶或檢索：同時引用攻擊者控制的**寫入**與之後**跨主體的讀取**或特權決策；只有共用紀錄、沒有可到達的消費者不夠
4. 動作綁定：確立刻意的請求或正規化後被核准的物件，與 handler 實際使用的物件比對；
   在本機觀察到未請求的動作、變更、重複或權限改變即停，不延伸成有害執行。schema 不一致：比對正規化驗證後的物件與 handler 的物件
5. MCP 身分：確認已驗證的連線、請求關聯、工具命名空間與實際憑證；需要外部伺服器身分或部署路由時判 `needs_validation`
6. 只有完整原始碼追蹤與實質結果才回報 `confirmed`；有特定未決的邊界事實時回報 `needs_validation`，並寫出解決它所需的本機檢查或擁有者觀察
