# 深度稽核的執行安全規則

> 改寫自 Cloudflare [security-audit-skill](https://github.com/cloudflare/security-audit-skill)
> （commit `c1c8a8c`）的 Universal execution safety 與 Local validation boundaries，
> MIT License，Copyright (c) 2025-2026 Cloudflare, Inc.；授權全文見 plugin 根目錄的 `THIRD_PARTY_NOTICES.md`。

本檔適用於 `deep-audit.md` 的**兩種模式**（指引與完整稽核），也適用於任何「為了確認漏洞而執行目標程式碼」的情境。
本知識庫的基本立場不變：**掃描由人執行**；深度稽核預設只讀原始碼。

---

## 1. 讀原始碼是唯讀的

閱讀、搜尋、追路徑都不需要執行任何東西。能用原始碼回答的，就不要執行。

## 2. 執行目標程式碼的前提：四項控制全部到位

目標控制的建置、測試、行程、瀏覽器、模擬器、fuzzer、fixture 處理，
**只能**在作業系統層級強制的沙箱內執行，且同時具備：

| 控制 | 要求 |
|---|---|
| 網路 | **不連外網**；需要本機 client／server 流量時，只用隔離的 loopback 網路命名空間 |
| 環境變數 | 從**空的環境**開始，只放明確允許清單內的安全值；`HOME`、暫存目錄、快取都指向 scratch 內 |
| 檔案系統 | 目標與工具鏈**唯讀**；目標行程只能寫自己的 `scratch/` |
| 資源 | 明確設定低的 CPU、記憶體、行程數、檔案大小、磁碟與執行時間上限——**每次**檢查都要，不只預期耗資源的 |

**任何一項無法落實，就不執行目標程式碼**：把缺少的沙箱能力列為 `needs_validation` 的阻礙，
附一份安全的驗證計畫。缺沙箱不會抹掉有原始碼依據的候選，只是它停在待驗證。

另外：

- **不安裝相依、不讓建置自行下載**；只用本機已有的工具與相依
- 建置一定要寫在原始碼旁時，可在 scratch 內做一份**可丟棄的原始碼副本**
- **絕不**把主機的家目錄、憑證、socket、共用服務、其他代理的目錄、保留的輸出目錄暴露給目標程式碼
- 指引模式下不保留任何目標產生的檔案

## 3. 沙箱內允許與禁止的事

**允許（僅限沙箱內）**：用既有相依離線建置；用假資料的隔離 loopback 行程；單元與整合測試；
小型 fixture 處理；sanitizer；有界的 fuzz／回歸測試；確定性的並行檢查；用假帳號的本機瀏覽器或模擬器測試；
用假身分在本機渲染 manifest 與評估政策；把外部或付費呼叫換成 mock。

**禁止**：

- 對線上或已部署系統發送任何流量；呼叫不是為這次隔離檢查而啟動的服務
- 透過網路安裝相依
- 使用**真實帳號或憑證**、**正式環境資料**、**其他使用者的資料**
- 碰觸共用佇列、雲端資源、CI runner、套件 registry、簽章或發布服務；發布任何成品
- 壓力測試、灌爆、產生費用（含付費 API 額度）
- 確立缺陷所需的最小效果之後，繼續做任何事

**可用性問題也一樣**：不對線上或共用行程測試可用性；改用程式碼層級的計算與本機有界迴圈證明。

## 4. 只用假資料

使用假主體、假 fixture、假的機密值。決定性的事實在原始碼或沙箱 fixture 之外時，
列為 `needs_validation`，請擁有者自己觀察（例如提供某個設定檔或路由規則），**不要自己去探測**。

> 與本知識庫其他規則一致：對已上線系統做任何主動掃描或探測，需要系統擁有者的**書面授權**，
> 而且那屬於人執行的弱點掃描或滲透測試，不在深度稽核的範圍內。

## 5. 重現紀錄怎麼寫

每個在本機重現的檢查記錄：指令、確切的測試輸入、沙箱的限制值，
以及**只限允許清單內**、重現所需的環境變數名稱與安全的非機密值。

- **絕不**擷取或複製當下的環境、繼承的變數、憑證值、登入狀態或不相關的主機路徑
- 從空環境啟動，而不是執行後再去遮蔽
- 證據路徑用 repo 相對路徑

## 6. 把 scratch 裡的結果保留下來

目標程式碼結束後，scratch 內的檔案仍視為**目標控制的不可信內容**。完整稽核模式下，
只有協調者端的可信程式碼可以把**事先宣告**的檔案搬到保留的 `artifacts/`，而且要防範路徑與連結攻擊：

1. 路徑必須是相對路徑，不得含絕對路徑、空段、`.`、`..` 或符號連結
2. 從事先開好的目錄描述符逐段以不跟隨連結（no-follow）的方式走，不以路徑重新開啟
3. 只接受**一般檔案**、連結數恰為 1、且在事先記錄的單檔與累計大小上限內；讀取時再檢查一次上限
4. 複製前後各做一次 `fstat`，身分、類型、連結數或大小有變就拒絕
5. 目的地同樣逐段 no-follow 建立，以排他方式建立檔案
6. **絕不**遞迴複製或 glob scratch、不在 artifacts 裡解壓縮、不搬符號連結、FIFO、socket、裝置、目錄、硬連結或正在變動的檔案
7. 任何一項檢查做不到或失敗，就丟棄該檔；它若是決定性證據，就把該紀錄留在 `needs_validation`，阻礙寫「無法安全保留證據」

## 7. 產出的保管

稽核產出含未修補的漏洞細節與重現方式：

- 輸出目錄預設放在目標 repo **之外**；要放在 repo 內必須確認已被 `.gitignore` 涵蓋
- **不得**放進公開 repo、議題追蹤或群組聊天；交付對象依專案的資安事件與保密規範決定
- 報告只寫原生介面的有界重現，不寫成對線上系統的攻擊步驟
