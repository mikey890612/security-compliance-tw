# check-id 對照表

本檔是 check-id 與各風險清單編號的**唯一**對照來源。
`checks/` 內不得出現任何法規或 OWASP 編號。

- 分級欄（普 / 中 / 高）依附表十的適用等級標記 ◎
- 附表十欄標「—（查檢表外）」者，表示該項目由本專案依 OWASP 等國際清單補充，
  不在附表十查檢表的收錄範圍內，但掃描器會標記
- **`MAS` 欄**為《行動應用 App 基本資安檢測基準》V4.0 的條號，
  **一律加 `MAS ` 前綴**——檢測基準與附表十的條號會字面撞車（兩者都有 `4.1.1`），
  不加前綴會讓稽核人員對錯表。條號全文見 `controls-mas-v4.md`

本檔共三張表：**Web**（`SAST-*` / `DAST-*`）、**行動端**（`MAST-*`）、
**MDM**（`MDM-*`，規格外的延伸）。三者對映的清單不同，混在一張表會產生大量噪音欄位。

> ⚠ **Web 表的 `MAS 4.2.2.1.2` 只提供檢測發現，不等於該項「符合」。**
> 該條要求的是「WebView 所連網域**應執行**安全檢測」——檢測有沒有真的被執行
> 是流程事實，不是程式碼事實，而本專案明文不執行任何掃描工具。
> 產出勾稽表時該項標「非程式碼可判定，需人工確認」，
> 把 `DAST-*` 的判定結果列為佐證，**不可據以直接標「符合」**。

## 刻意放寬分級之處

以下 check 的分級比附表十原文寬，理由是掃描器不分等級一律會標，
若照原文只標高等級，普 / 中專案會漏掃而在送掃時被打回：

| check-id | 附表十原文分級 | 本表分級 | 理由 |
|---|---|---|---|
| SAST-CRYPTO-001 | 高（4.6.1 未遭破解之演算法） | 中 · 高 | gosec G401 / bandit B324 對所有專案都會報 MD5/SHA1 |
| SAST-CRYPTO-003 | 查檢表外 | 中 · 高 | 弱亂數用於 token 產生時等同鑑別缺陷 |
| SAST-LLM-* | 查檢表外 | 普 · 中 · 高 | 由專案是否具備 AI 功能決定載入，非由等級決定 |

產出 `checklist.md` 時**以附表十原文分級為準**，本表的放寬只影響
`profile.md` 的 check 選取，不影響勾稽表內容。

## 本專案補充的類別

下列類別由本專案依 OWASP 等國際清單補充，附表十查檢表未收錄，
但掃描器會標記：

- **API 物件層級授權**（BOLA / BOPLA / BFLA）——附表十的存取控制以頁面層級為主
- **API 資產盤點**——影子 API、殭屍 API
- **LLM / Agent 風險**——提示注入、過度代理權、系統提示洩漏
- **行動 App / MDM**——不安全本機儲存、弱密碼學、明文傳輸、本機驗證繞過、IPC／Deep Link、敏感日誌、WebView；以及 EMM／MDM 註冊、受管 App、遠端抹除
- **供應鏈**——附表十收錄「元件漏洞通告」，本專案另補建置流程與發布管道

這些項目在本表中「附表十」欄標為「—（查檢表外）」。
產出 `checklist.md` 時不會出現在正式勾稽表上，
但**仍應修**——掃描器會標記，驗收一樣過不了。

## 行動端對照表（`MAST-*`）

行動端對映的清單與 Web 端不同，因此另立一張表——
`Web21` / `Web25` / `API23` / `LLM25` 對行動 check 是純噪音，反之亦然。

- `L1` / `L2` / `L3` 為《行動應用 App 基本資安檢測基準》的 App 分類；
  `F` 為高安全性 App 的進階加測項目（逆向工程與竄改防護），由送檢單位自行選擇；
  `參` 表示該條在該基準中屬**參考項目**（非必要檢測項目）。
  分級值直接取自 `controls-mas-v4.md`，不另行判斷
- **`參` 不可用 `L1◎` 代替**——`L1◎` 的意思是「L1 類 App 必須符合」，
  拿它標參考項目等於在勾稽表上謊報必要性
- **`平台` 欄決定驗證器要求的程式碼範例語言**：
  `Android`→ kotlin、`iOS`→ swift、`雙平台`→ 兩者、`設定檔`→ xml/plist/gradle 任一。
  一律要求兩種語言會逼出變形內容：純設定檔議題只能把 manifest 屬性
  當註解塞進 kotlin 區塊湊數，而那正是掃描器要比對的東西
- `MASVS` 欄只填控制項編號，**不抄其敘述文字**——MASVS 為 CC BY-SA 4.0，
  具傳染性，與本專案的 MIT 不相容；編號本身不構成著作重製
- `附表十` 欄多為 `—（查檢表外）`：附表十是伺服器視角的資通系統防護基準，
  行動端多數議題不在其收錄範圍。**行動 App 的驗收依據通常是檢測基準，不是附表十**
