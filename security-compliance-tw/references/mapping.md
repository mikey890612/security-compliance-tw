## 4.5.3 開發階段的條目層級對照

附表十查檢表在 4.5.3 底下有 **6 個獨立條目**，但本表的子碼只有 `.1` `.2` `.4` 三種。
產出勾稽表時若只看子碼，無法決定某個 check 對應到哪一條，不同人會拆出不同答案。
**逐條對應以本表為準：**

條目文字與 `controls-appendix10.md` **逐字一致**，可直接用於比對。

| 查檢表條目 | 適用分級 | 對應 check-id |
|---|---|---|
| 具有防範 SQL 命令注入攻擊(SQL Injection)之措施 | 普中高 | `SAST-INJ-001`、`SAST-LLM-002` |
| 具有防範跨站腳本攻擊(XSS)之措施 | 普中高 | `SAST-INJ-004` |
| 具有防範跨站請求偽造(CSRF)攻擊之措施 | 普中高 | `DAST-COOKIE-003` |
| 發生錯誤時，使用者頁面僅顯示簡短錯誤訊息及代碼，不包含詳細的錯誤訊息 | 普中高 | `SAST-ERR-001`、`DAST-LEAK-001` |
| 所有功能皆進行錯誤及例外處理，並確保將資源正確釋放 | 普中高 | `SAST-ERR-002`、`SAST-ERR-003`、`SAST-ERR-004` |
| 具備系統嚴重錯誤之通知機制(例如電子郵件或簡訊) | **高** | **無對應 check**——本知識庫未涵蓋，勾稽表標「非程式碼可判定」 |

另外兩項不在查檢表中：

| 項目 | 對應 check-id | 說明 |
|---|---|---|
| HTTP 安全標頭（4.5.3.4） | `DAST-HDR-001~003` | V3.2 內文新增但查檢表未同步，見 `controls-appendix10.md` 的版本落差 |
| OS 命令注入 | `SAST-INJ-002` | 查檢表的開發階段只列 SQL／XSS／CSRF 三種注入，未含 OS 命令注入。**掃描器一律標 Critical，務必修**，勾稽表列入「未列但掃描會抓」區段 |

## 刻意放寬分級之處

以下 check 的分級比附表十原文寬，理由是掃描器不分等級一律會標，
若照原文只標高等級，普 / 中專案會漏掃而在送掃時被打回：

| check-id | 附表十原文分級 | 本表分級 | 理由 |
|---|---|---|---|
| SAST-CRYPTO-001 | 高（4.6.1 未遭破解之演算法） | 中 · 高 | gosec G401 / bandit B324 對所有專案都會報 MD5/SHA1 |
| SAST-CRYPTO-003 | 附表十無對應項 | 中 · 高 | 弱亂數用於 token 產生時等同鑑別缺陷 |
| SAST-LLM-* | 附表十無對應項 | 普 · 中 · 高 | 由專案是否具備 AI 功能決定載入，非由等級決定 |

產出 `checklist.md` 時**以附表十原文分級為準**，本表的放寬只影響
`profile.md` 的 check 選取，不影響勾稽表內容。

## 已知缺口

附表十完全未涵蓋、但掃描器會抓的類別：

- **API 物件層級授權**（BOLA / BOPLA / BFLA）——附表十的存取控制是頁面級思維
- **API 資產盤點**——影子 API、殭屍 API
- **LLM / Agent 風險**——提示注入、過度代理權、系統提示洩漏
- **供應鏈**——附表十只到「元件漏洞通告」，未及建置流程與發布管道

這些項目在本表中「附表十」欄標為「—（缺口）」。
產出 `checklist.md` 時，這些項目不會出現在勾稽表上，
但**仍應修**——掃描器會標，驗收一樣過不了。
