# 附表十 資通系統防護基準（應用程式層）

**來源：《資通安全責任等級分級辦法》附表十「資通系統防護基準」**
（依《資通安全管理法》授權訂定之法規命令）。

本檔收錄的控制措施與分級標記出自上述**法規命令**本身。
依著作權法第 9 條，憲法、法律、命令或公文不得為著作權之標的。

《Web 應用程式安全參考指引》（數位發展部資通安全署）為前述法規之
實作參考文件，其**實作建議、程式範例與編排**屬該署所有，
不在本專案重製範圍內——本專案的實作內容係另行以 Go / Python / JavaScript
撰寫，並補上掃描器對應。

**本檔僅在產出 `checklist.md` 時讀取。** 平時稽核走 `checks/` 與 `mapping.md`。

適用分級以 ◎ 標記。空白代表該等級不要求。

## 4.4 識別與鑑別

### 4.4.1 內部使用者之識別與鑑別

| 實作項目 | 普 | 中 | 高 |
|---|:-:|:-:|:-:|
| 採用多重因素身分鑑別(兩種以上驗證類型) | | | ◎ |
| 資訊系統在建立連線前，應識別允許存取之特定來源(如 IP) | | | ◎ |

### 4.4.2 身分鑑別管理

| 實作項目 | 普 | 中 | 高 |
|---|:-:|:-:|:-:|
| 確實規範使用者密碼強度(密碼長度 12 個字元以上、包含英文大小寫、數字，以及特殊字元) | ◎ | ◎ | ◎ |
| 使用者必須定期更換密碼，且至少不可以與前 3 次使用過之密碼相同 | ◎ | ◎ | ◎ |
| 具備帳號鎖定機制，身分鑑別失敗達 5 次後，至少 15 分鐘內不允許該帳號及來源 IP 繼續嘗試登入 | ◎ | ◎ | ◎ |
| 身分鑑別相關資訊不以明文傳輸 | ◎ | ◎ | ◎ |
| 採用圖形驗證碼(CAPTCHA)機制於身分鑑別及重要交易行為 | | ◎ | ◎ |
| 密碼重設機制對使用者重新身分確認後，發送一次性及具時效性令牌(Token)，檢查有效性後才允許重設 | | ◎ | ◎ |

### 4.4.3 鑑別資訊回饋

| 實作項目 | 普 | 中 | 高 |
|---|:-:|:-:|:-:|
| 資訊系統應遮蔽在鑑別過程中之資訊(如密碼)，以防止未授權之使用者窺探/使用 | ◎ | ◎ | ◎ |

### 4.4.4 加密模組鑑別

|---|:-:|:-:|:-:|
| 密碼添加亂數(Salt)進行雜湊函式(HASH Function)處理後，分別儲存亂數及雜湊後密碼 | | ◎ | ◎ |

**4.5.3.4 HTTP 安全標頭防護與設定**（V3.2 新增，適用分級 中◎ 高◎）
收錄於指引內文表 71 與附件 3，附件 1 查檢表未收錄對應條目。

實務影響：弱點掃描會標記安全標頭（`DAST-HDR-*`、`DAST-COOKIE-*`），
但稽核人員手上的查檢表可能沒有這一列。產出 `checklist.md` 時，
建議把這類項目另立「查檢表外的掃描項目」區段，與正式勾稽表分開呈現。

## 產出 checklist.md 的規則

1. 依專案分級篩選：只列該等級標 ◎ 的項目
2. 每個項目經 `mapping.md` 反查對應的 check-id，帶入該 check 的判定結果
3. 一個項目對應多個 check 時，全部通過才標「符合」
4. 找不到對應 check 的項目（如備份備援、系統文件、委外合約），
   標「非程式碼可判定，需人工確認」——**不要臆測結果**
5. `mapping.md` 中附表十欄為「—（查檢表外）」的 check，
   另立「查檢表外的掃描項目」區段
